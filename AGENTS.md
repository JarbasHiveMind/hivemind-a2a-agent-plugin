# AGENTS.md — `hivemind-a2a-agent-plugin`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

An agent-protocol plugin for [HiveMind](https://github.com/JarbasHiveMind)
that bridges satellite utterances to an external
[A2A (Agent-to-Agent)](https://google.github.io/A2A/) server over JSON-RPC 2.0
(`tasks/send` / `tasks/sendSubscribe`). It registers `A2AAgentProtocol` under
the `hivemind.agent.protocol` entry-point group, implementing the
`AgentProtocol` interface from
[hivemind-plugin-manager](https://github.com/JarbasHiveMind/hivemind-plugin-manager).
The hub is [HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core);
the wire protocol and specs live in the architecture docs. Agent plugins like
this one are the modern replacement for the old solver pipeline
(`opm.agents.chat`) — do not add new solver-based code here.

## Layout / build / test

- Package module: `hivemind_a2a_agent_plugin/` (`__init__.py` holds
  `A2AAgentProtocol`, `_client.py` holds the JSON-RPC `A2AClient`). Tests live
  in `tests/` (unit tests at the top level, `tests/e2e/` for the mock-server
  end-to-end suite) — do not create a second test directory.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest tests -q`. The e2e tests
  in `tests/e2e/` spin up a mock A2A server (`tests/e2e/mock_a2a_server.py`
  via `uvicorn`/`fastapi`) — they need the `test` extra installed, not a live
  external service.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is
  a bug to FIX at the source, not to work around with a pin downgrade.

## Working agreement (org-wide law)

- **Git identity is always** `JarbasAi <jarbasai@mailfence.com>`. Never set a
  per-repo override.
- **Never push `dev` or `master`.** Work on a feature branch and open a
  **draft** PR into `dev`. A human merges. You do not merge your own PRs.
- **Never merge or modify `Release X → master` PRs.** They are the maintainer's
  stable-release mechanism, generated by automation.
- **One commit per PR** (squash before pushing). Conventional commits; `feat:`
  only for a user-visible new capability. `fix:`, `docs:`, `chore:`, `ci:`
  otherwise.
- **Disclose AI authorship.** Every PR/issue/comment an agent writes carries, at
  the top: `> 🤖 Auto-generated by <model> via Claude Code — NOT human-reviewed.
  Verify before acting.` PR bodies are plain human prose (3–6 short paragraphs),
  no tables or section-symbol spray.
- **Never edit someone else's** issue, PR description, or comment. Add a comment
  instead; on your own PRs, edit the body rather than piling on comments.
- Keep durable text (README, docs, PR bodies, comments) timeless and standalone:
  no dates, no "currently/now/new", no meta-commentary about the edit itself.
- No scratch files, committed virtualenvs, `__pycache__`, `.pyc`, `.egg-info`,
  or build artifacts in a PR. `git show --stat` shows only intended files.

## Dependencies

- **Floor pins only** (`>=X.Y.Za1`), bumped when a feature or fix is actually
  needed — with a one-line comment saying why. No upper caps unless a specific
  released version is genuinely broken (say which and why). `pyproject.toml`
  currently pins `ovos-utils` and `hivemind-plugin-manager` with upper caps
  (`<1.0.0`); that is a deviation from this rule, not a pattern to copy — drop
  the cap the next time either dependency is touched.
- **No lockfiles, ever.** Target the latest alphas (`--prerelease=allow`).
- Everything in `pyproject.toml` (deps, metadata, version). Never install from
  git — depend on a published PyPI alpha.
- Apache-2.0. Do not add GPL/AGPL dependencies.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- This plugin is an outbound bridge, not the auth/ACL hot path — it forwards
  already-authenticated satellite utterances to the configured A2A server and
  does not itself resolve API keys or ACLs. It still must fail safe: with no
  `agent_url` configured, `natural_language_query` yields an explicit error
  string rather than raising or silently answering nothing (`__init__.py`).
- Never let an A2A-server failure (unreachable host, timeout, empty response,
  JSON-RPC error object) propagate as an unhandled exception or a silent
  empty reply — always yield a human-readable error chunk followed by the
  `None` sentinel so the satellite gets a reply.
- `session_id` maps 1:1 to the A2A `sessionId`. The plugin is stateless with
  respect to conversation history — the A2A server owns it. Do not add local
  session caching; if a cache is ever introduced it needs an identity guard
  and write-invalidation, matching the rest of the HiveMind plugin family.
- Preserve wire compatibility with the A2A JSON-RPC 2.0 methods
  (`tasks/send`, `tasks/sendSubscribe`) in `_client.py` — this plugin is a
  client of an external, non-HiveMind protocol, so breaking changes there
  affect every configured A2A backend, not just HiveMind-side consumers.
